# Image understanding and face recognition

- Add one image attachment path for CLI files, Mimo photos, and browser uploads; keep the existing agent loop and provider adapters.
- Ship screenshot/photo understanding first, with validated image formats, bounded payloads, and verified model support.
- Add a separate, opt-in face matcher for identities explicitly enrolled by the user; return `unknown` when uncertain.
- Reuse session ownership, storage, and event delivery across clients; prove image quality, identity isolation, and deletion before rollout.

**Current state.** [providers.py](../agent_loop/providers.py) accepts text messages; [tools.py](../agent_loop/tools.py) returns text plus metadata. [loop.py](../agent_loop/loop.py) already appends tool results, and [runtime.py](../agent_loop/runtime.py) owns filesystem/process access. Vision and face matching are unimplemented. [OpenAI Responses supports image/file tool outputs](https://developers.openai.com/api/docs/guides/function-calling#formatting-results); a shared attachment path also supports other provider formats.

**Smallest implementation.** Add `image_view(paths)` and repeatable `--image`. Carry attachment references in `ToolResult.metadata`; append one image-bearing user message after **all** pending tool results, preserving tool-call pairing. Extend provider serialization for text/image parts, keeping plain strings compatible. Verify vision capability per backend/model, including fallback, and reject unsupported selections before sending. Runtime reads only permitted session files; a pure converter validates bytes, corrects orientation, strips location metadata, and preserves screenshot legibility. Start with JPEG/PNG/HEIC; defer RAW/PDF. Use configurable defaults of eight images per call, 20 per context, 1568-pixel longest edge and 500 KB per image; reject or explain quality reduction. Use [SESSIONS.md](SESSIONS.md)'s immutable attachment store outside workspace Git/traces; preserve reopenable references through compaction.

**Face matching.** Detection locates faces; recognition compares them with enrolled identities. Evaluate one [Rekognition collection adapter](https://docs.aws.amazon.com/rekognition/latest/dg/collections.html) through Runtime and the host credential boundary before choosing a provider. Store identity IDs and biometric templates (numeric face representations) separately from conversational memory, partitioned by authenticated user. Enrollment records consent and labeled reference photos; deletion removes references/templates. Calibrate similarity thresholds on representative photos and return `unknown` for ambiguous matches. The LLM explains matcher results; it does not invent identities. Matching must not authenticate users.

**Clients.** [Mimo](../../pet-moment/mobile-app/Mimo/Agent/AgentClient.swift) already streams text/events through its [gateway](../../pet-moment/mobile-app/gateway/server.py); camera capture, permission text, upload, and image display are new. Add one authenticated upload endpoint returning a session-owned attachment ID, then associate it with the intended voice/text turn. CLI uses read-only input mounts; a new browser voice client shares uploads/events. Identity enrollment waits for per-user ownership rather than relying on the existing shared connection token.

**Acceptance.** Test both provider wire formats, malformed/oversized images, image questions against a blind control, unknown/lookalike faces, cross-user denial, deletion, and attachment recovery after compaction/resume. Demonstrate one photo question and one enrolled/unknown match from CLI and Mimo; reuse the same contract for browser voice.
