# Gmail, Calendar, and work tools

- Add explicit Gmail search/read and Calendar list/free-busy tools to the existing registry; return bounded results with provider IDs, links, pagination cursors, and timezone-aware dates. Start with reads, then add drafts, sending, and event changes as separate operations.
- Implement one small Google client with an injectable HTTP transport, following `WebClient`; obtain short-lived access tokens through Runtime under [USER_ENV.md](USER_ENV.md); durable secrets stay on the host. Extend the documented network boundary deliberately; tools must not give tokens or authenticated arbitrary-URL fetching to model-written shell commands.
- Before each write, resolve the exact account, recipients, content, calendar, and timezone. Execute under the user's existing authorization; otherwise return a concrete proposal for confirmation. Persist operation intent and results in [SESSIONS.md](SESSIONS.md) before enabling writes; reconcile uncertain outcomes before retrying. [JOBS.md](JOBS.md) reuses these records.
- Reuse these tools across CLI, voice, and Mimo. Add Drive search/read and Airtable record access only for a concrete workflow, using the same account binding and result format; avoid introducing a general connector framework initially.

**Current baseline.** [tools.py](../agent_loop/tools.py) provides `ToolRegistry`, tool allowlists, and capped `ToolResult` output; there are no Gmail or Calendar adapters. [web.py](../agent_loop/web.py) already demonstrates a trusted network client with injectable transport. [voice/bridge.py](../voice/bridge.py) uses the same registry as the CLI. Authentication, refresh, revocation, and verified user-to-account binding are prerequisites owned by [USER_ENV.md](USER_ENV.md). Operations requiring durable API tokens execute on the host through the same narrow control boundary.

**Integration.** Mimo's [gateway](../../pet-moment/mobile-app/gateway/server.py) launches the container bridge, but `public_event` reduces tool events to `thinking`; its [AgentClient](../../pet-moment/mobile-app/Mimo/Agent/AgentClient.swift) consumes text answers. Summaries fit that contract. Add an allowlisted proposal/result event and UI only when structured previews are needed. The current shared bearer token does not identify users; bind authenticated users to sessions before connecting accounts. Standalone CLI needs no mobile dependency. Browser voice UI is absent; build a thin client over the gateway's voice transport with the same proposal state and authorization checks.

**Google feasibility.** Request only needed permissions: `gmail.readonly` for mail reads and appropriate Calendar read/free-busy scopes. Gmail read access is a restricted scope; public rollout must account for verification and any applicable server-data security assessment. Sources: [Gmail scopes](https://developers.google.com/workspace/gmail/api/auth/scopes), [Calendar scopes](https://developers.google.com/workspace/calendar/api/auth).

**Done when:** one connected user can summarize mail and availability through CLI and Mimo/voice; paginated reads, DST boundaries, revoked access, and cross-user isolation pass; an authorized send/event creation survives a simulated ambiguous timeout without duplicate writes. External message content never supplies authorization.
