# CLI sessions, volume mounts, and resume

- Install and launch agent-loop as a local interactive CLI, like Claude Code. The launcher runs on the user's machine; the agent runs inside a local container and accesses host folders through volume mounts.
- Add a `mount_volume(host_path, read_only=true)` tool the agent can invoke during a conversation. Return the mounted container path so existing filesystem and shell tools can browse and work with the host files.
- Route mount requests through the runtime to the host launcher, which validates the requested path and manages the mount. Keep Docker access in the launcher; preserve the conversation if mounting requires recreating the container.
- Mount folders read-only by default; allow writable mounts when requested by the user. Writes affect the host files directly. Exclude mounted folders from workspace Git, snapshots, and reset/clean operations.
- Give each session an ID. Before managed teardown, finish the current tool turn, quiesce writers, and save the conversation and container filesystem, including `/work` and installed packages. Remove the container only after the save succeeds. Resume by ID into a fresh container with the saved files, conversation, configuration, and mounts; RAM and running processes are not restored.
- Store everything locally under `~/.local/state/agent-loop/` (or `$XDG_STATE_HOME/agent-loop/` when set). Each `sessions/<id>/` directory contains `metadata.json` (session ID, snapshot references, image ID, nonsecret configuration, mount mappings, and timestamps), conversation/context JSON files, and container snapshot archives. The launcher owns this directory outside the agent workspace and atomically updates metadata after snapshot files are fully saved. Keep credentials separate per [USER_ENV.md](USER_ENV.md).
- Save filesystem changes as an image with [Docker commit](https://docs.docker.com/reference/cli/docker/container/commit/) and archive it with [Docker save](https://docs.docker.com/reference/cli/docker/image/save/). Mounted host data stays in its original location and is reattached on resume; fail clearly if a mount is unavailable. Keep credentials out of saved image files and configuration. Rewind/fork and shared client infrastructure remain out of scope; this plan supersedes [RUNTIME.md](RUNTIME.md)'s mount/session restrictions.
